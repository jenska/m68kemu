# Plan: MC68010

This is phase 2 of the [roadmap](roadmap.md). It adds the MC68010 as a second
model on top of the per-model dispatch tables from phase 1. The MC68000 keeps
its behaviour and timing; every change below applies only when a CPU is
created with `WithModel(M68010)`.

## Programming Model

* **Control registers.** `Registers` gains `VBR` (vector base register),
  `SFC` and `DFC` (source and destination function code, 3 bits each).
  Reset clears all three. On the MC68000 they stay zero.
* **Vector table.** Every vector is read from `VBR + 4*vector`. The reset
  vectors are still read from address 0, because reset clears the VBR first.

## Instructions

| Instruction | Encoding | Notes |
| --- | --- | --- |
| `MOVEC Rc,Rn` / `MOVEC Rn,Rc` | `$4E7A` / `$4E7B` + extension word | privileged; control registers SFC (`$000`), DFC (`$001`), USP (`$800`), VBR (`$801`); any other register raises the illegal-instruction exception |
| `MOVES <ea>,Rn` / `MOVES Rn,<ea>` | `$0E00` + extension word | privileged; memory-alterable `<ea>`; reads with the function code in SFC, writes with the one in DFC; byte and word loads into An are sign-extended |
| `RTD #d16` | `$4E74` + displacement | pops the PC, then adds the sign-extended displacement to SP |
| `MOVE CCR,<ea>` | `$42C0` | data-alterable `<ea>`; writes the CCR as a word with the upper byte zero |
| `MOVE SR,<ea>` | `$40C0` | now privileged |
| `BKPT #n` | `$4848`–`$484F` | no change needed: without external hardware that answers the breakpoint acknowledge cycle, the 68010 takes the illegal-instruction exception, which the empty table slot already does |

The bus has no notion of address spaces, so the function code of a MOVES
access is only visible in bus traces and in the status word of a fault.

## Exception Stack Frames

From the 68010 on, every frame ends with a format/vector word: bits 15–12
hold the format, bits 11–0 the vector offset (vector × 4).

* **Format $0** (4 words): SR, PC, format/vector word. Used by every
  exception except bus and address errors, including interrupts, TRAP, CHK,
  divide by zero, TRAPV, privilege violation, illegal instruction and
  line A/F.
* **Format $8** (29 words), for bus and address errors:

  | Offset | Content |
  | --- | --- |
  | 0 | SR |
  | 2 | PC |
  | 6 | `$8` / vector offset |
  | 8 | special status word (SSW) |
  | 10 | fault address |
  | 14 | reserved |
  | 16 | data output buffer |
  | 18 | reserved |
  | 20 | data input buffer |
  | 22 | reserved |
  | 24 | instruction input buffer |
  | 26–57 | internal information (16 words) |

  SSW bits: 15 RR (rerun), 13 IF (instruction fetch), 12 DF (data fetch),
  11 RM (read-modify-write), 10 HB (high byte), 9 BY (byte transfer),
  8 RW (1 = read), 2–0 function code.

* **RTE** reads the format word. Format $0 pops 4 words, format $8 pops 29
  words, and any other format raises the new format-error exception
  (vector 14).

### Resuming After a Bus Error

The real 68010 saves its internal state in the format $8 frame and continues
the interrupted instruction after RTE. This emulator executes each instruction
as a unit and has no such internal state. It uses **instruction restart**
instead:

* At the start of each instruction, a 68010 CPU saves its registers.
* On a bus or address error, the registers go back to that saved state, and
  the frame's PC is the address of the faulting instruction.
* RTE from a format $8 frame therefore runs the whole instruction again.

This gives a handler the behaviour a virtual-memory system needs: fix the
cause, RTE, and the instruction completes. The differences from the hardware:
memory writes the instruction made before the fault happen a second time, the
RR bit is ignored (the faulted cycle always reruns, as part of the restart),
the internal information words are zero, and the data and instruction input
buffers are zero.

## Timing

The 68010 runs many instructions in fewer cycles than the 68000, has longer
exception processing because of the format word, and has a loop mode for
DBcc loops. This phase reuses the MC68000 cycle tables for the 68010, so its
timing is approximate. Exact 68010 timing needs the tables from the MC68010
section of the M68000 User's Manual and is a follow-up.

## Commit Sequence

1. Accept `M68010` in `NewCPU`; add VBR, SFC and DFC; read vectors relative
   to the VBR.
2. The new instructions and the 68010 opcode-validity map.
3. Format $0 and $8 frames, RTE with format checks, the format-error
   exception and instruction restart after bus and address errors.
4. README, CHANGELOG and roadmap.

## Tests

* The MC68000 opcode snapshot stays unchanged, and a second snapshot covers
  the 68010 table.
* Each new instruction, including privilege violations and invalid MOVEC
  registers.
* Frames: format $0 for a TRAP and an interrupt with a non-zero VBR; format
  $8 contents for a read and a write fault.
* RTE: format $0, format $8 restart (a bus error on a write to a device that
  fails once, then succeeds), and a format error.
