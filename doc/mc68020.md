# Plan: MC68020 and MC68030

This is phase 3 of the [roadmap](roadmap.md). It adds the MC68020 and the
MC68030 integer units, 32-bit addressing and the coprocessor interface. The
MC68030's MMU follows in phase 5. The FPU's F-line instructions (4c) came
after this phase and are done ([fpu.md](fpu.md)). The MC68000 and MC68010 keep their behaviour and speed.

From the 68020 on, exact cycle timing is out of reach (caches, pipeline,
overlapped execution). Timing is an approximation; the goal is correct
behaviour.

**Status: done**, except `CALLM`/`RTM`. Notes from the implementation:

* The 68000's speed is unchanged within noise after every step. Two first
  versions cost 2-13% and were reworked: the 32-bit page table keeps the
  first 16 MB inline and its lookup small enough to inline, and 32-bit
  branches have their own handler instead of a test in `branch`.
* The FMOVEM register masks follow MAME/Musashi (control and
  postincrement: bit 7 is FP0; predecrement: bit 0 is FP0). m68kasm used
  the integer MOVEM masks until v1.6.3, which also fixed its swapped
  memory indirect preindexed/postindexed encodings and added the full
  extension word syntax (suppressed registers, long base displacements)
  the tests use.

## Steps

### 3a. 32-bit addresses and misaligned operands

* **CPU address mask** per model: 24 bits for the 68000 and 68010, 32 bits
  for the 68020 and 68030. The ~25 hard-coded `& 0xffffff` in the CPU become
  `cpu.addrMask`. This touches the hottest paths and gets its own benchmark
  comparison.
* **Bus address width.** `NewBus` stays 24-bit. A new option makes a bus
  32-bit: device decoding then uses a two-level page table (top byte, then
  64 KB pages, allocated only where devices sit), so a 24-bit bus keeps its
  current single-level lookup.
* **Misaligned operands.** The 68020 accepts word and long operands at odd
  addresses. The CPU splits such an access into aligned byte and word
  accesses, so devices still see aligned cycles. Instruction fetches from an
  odd address still raise an address error.

### 3b. Programming model and exception frames

* `M68020` and `M68030` models; `Registers` gains `MSP`, `CACR` and `CAAR`
  (`SSP` is the interrupt stack pointer, ISP). The M bit (SR bit 12) selects
  MSP or ISP in supervisor mode.
* MOVEC adds CACR (`$002`), CAAR (`$802`), MSP (`$803`) and ISP (`$804`).
  There are no caches to emulate; CACR and CAAR only hold values, and the
  CACR's write-only cache-clear bits read as zero.
* Frames:

  | Format | Words | Used for |
  | --- | --- | --- |
  | $0 | 4 | most exceptions, interrupts |
  | $1 | 4 | throwaway frame on the ISP when an interrupt arrives with M set |
  | $2 | 6 | CHK, CHK2, TRAPcc, TRAPV, trace, divide by zero, coprocessor post-instruction (+ instruction address) |
  | $9 | 10 | coprocessor mid-instruction (+ instruction address, 4 internal words) |
  | $A | 16 | short bus cycle fault |
  | $B | 46 | long bus cycle fault |

  Layouts after SR, PC and the format/vector word, from the Linux kernel's
  `arch/m68k/include/asm/traps.h`: format $A has the special status word at
  offset 10, the data fault address at 16 and the data output buffer at 24;
  format $B adds the stage B address at 36, the data input buffer at 44 and
  the version number in the top nibble of the word at 54. SSW bits: FC, FB,
  RC, RB (15-12), DF (8), RM (7), RW (6), SIZE (5-4), function code (2-0).

* Bus and address errors push a format $B frame and use instruction restart
  as on the 68010 ([mc68010.md](mc68010.md)): the registers roll back to the
  start of the instruction and RTE runs it again. The SSW reports a data
  fault with DF and the data fault address, an instruction fetch fault with
  FB and RB and the stage B address. The short format $A is not produced;
  RTE accepts it.
* RTE accepts formats $0, $1, $2, $9, $A and $B and raises the format error
  for others. A format $1 frame is popped and RTE continues with the frame on
  the stack its SR selects.

### 3c. Addressing modes

* The brief extension word scales the index by 1, 2, 4 or 8 (bits 10-9).
* The full extension word (bit 8 set): base and index suppress, base
  displacement (null, word, long), memory indirect pre- and post-indexed
  with outer displacement, for (An) and PC-relative modes.

### 3d. Instructions

* 32-bit branch displacements (`Bcc.L`, `BRA.L`, `BSR.L`: an 8-bit
  displacement of `$FF`), `LINK.L`, `CHK.L`, `EXTB.L`.
* `MULU.L`, `MULS.L` (32 and 64-bit results), `DIVU.L`, `DIVS.L`, `DIVUL.L`,
  `DIVSL.L`.
* `TST` with An, PC-relative and immediate operands; `CMPI` with
  PC-relative operands.
* `TRAPcc`, `BKPT` (illegal without breakpoint hardware), `PACK`, `UNPK`.
* Bit fields: `BFTST`, `BFEXTU`, `BFCHG`, `BFEXTS`, `BFCLR`, `BFFFO`,
  `BFSET`, `BFINS`.
* `CAS`, `CAS2`, `CHK2`, `CMP2`.
* `CALLM` and `RTM` (68020 only) are left out at first: almost no software
  uses them, and the 68030 dropped them. They raise the illegal-instruction
  exception until implemented.

### 3e. Coprocessor interface

F-line instructions with coprocessor ID 1 (cpGEN, cpBcc, cpScc, cpDBcc,
cpTRAPcc, cpSAVE, cpRESTORE) go to an attached coprocessor through a small
interface in the core; without one they raise the line-F exception. The FPU
attaches in 4c through `fpu.FPU.Coprocessor`, reusing the command and
operand handling of `fpu.CIR`. A coprocessor that also implements
`CoprocessorTiming` runs concurrently with the CPU and stalls its next
instruction until it is done.

### 3f. MC68030

The 68030 integer unit is the 68020's without `CALLM`/`RTM` and with its
own CACR bits. Its MMU instructions raise the line-F exception until
phase 5.

## Sources

Encodings are checked against `m68kasm` and `m68kdasm`, which implement the
68020 instruction set and extension words. Frame layouts and SSW bits are
from the Linux kernel, which decodes them on real 68020/030 machines. The
Motorola manuals could not be downloaded from bitsavers or NXP.

## Tests

* The opcode snapshots for the 68000 and 68010 stay unchanged; new
  snapshots cover the 68020 and 68030 tables.
* Each step adds tests for its instructions, modes and frames; the
  concurrency test gains a 68020.
* Benchmarks for the 68000 stay within noise after 3a.
